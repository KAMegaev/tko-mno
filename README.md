# Расчёт мест накопления отходов

Веб-страница, которая сводит выгрузку реестра мест накопления отходов (МНО) по
муниципальным образованиям и заполняет шаблон «Приложение 8.2».

**Сайт:** https://kamegaev.github.io/tko-mno/

Все вычисления выполняются в браузере: загруженные файлы никуда не отправляются
и не сохраняются на сервере. Сервера у страницы нет — это статические файлы.

## Как пользоваться

1. **Файлы.** Загрузите два файла `.xlsx`: выгрузку реестра МНО и шаблон приложения 8.2.
2. **Столбцы.** Программа сама находит нужный лист, шапку и столбцы в обоих файлах.
   Проверьте распознавание и при необходимости выберите столбцы вручную.
3. **Муниципальные образования.** Показывается таблица соответствий «реестр → шаблон»:
   что нашлось точно, что подобрано по схожести названий, чего нет вовсе. Правится вручную.
4. **Результат.** Контрольные суммы, отчёт о проблемах и сохранение заполненного файла
   в выбранную папку.

Для каждого нового региона загружаются свои два файла — ничего в коде менять не нужно.

## Правила заполнения

| Столбец шаблона | Что попадает |
|---|---|
| Количество МНО | число записей (строк) реестра по муниципальному образованию |
| Количество МНО с раздельным сбором | число записей, где «Контейнеры (бункеры) для раздельного накопления ТКО → Количество, шт.» > 0 — по контейнерам, а не по отметке «Наличие раздельного накопления» |
| Количество контейнеров: Смешанные ТКО | сумма «Контейнеры для совместного накопления ТКО → Количество, шт.» |
| Количество контейнеров: Раздельный сбор | сумма «Контейнеры для раздельного накопления ТКО → Количество, шт.» |
| Количество контейнеров: КГО | сумма «Контейнеры для крупногабаритных отходов → Количество, шт.» |
| Количество контейнеров: Иное | сумма «Иные контейнеры (бункеры) → Количество, шт.» |
| Потребность в… | остаётся пустым — таких данных в выгрузке нет |

Заполняется первая по порядку вкладка с таблицей сведений о местах (площадках)
накопления. Столбцы и порядок строк с наименованиями субъектов и муниципальных
образований не меняются. В конце таблицы добавляется строка **ИТОГО** с формулами
`SUM(...)` по каждому заполненному столбцу.

### Контейнеры без разбивки по группам

В реестре встречаются строки, где заполнено «Общее количество контейнеров», но все
четыре столбца с разбивкой по группам пусты. Такие контейнеры по умолчанию относятся
к «Смешанные ТКО» — тогда сумма по столбцам E:H сходится с «Общим количеством
контейнеров» из реестра. На шаге 2 правило можно изменить: отнести к «Иное» или не
учитывать вовсе. Количество таких строк и контейнеров всегда показано в отчёте.

## Что программа сохраняет в файле

Шаблон не пересобирается, а патчится: в исходном `.xlsx` меняются только нужные ячейки.
Поэтому в готовом файле сохраняются оформление, объединённые ячейки, выпадающие списки
(проверка данных), настройки печати и все служебные части книги. Формулы записываются
вместе с посчитанными значениями и помечены на пересчёт при открытии, поэтому файл
корректно открывается и в Excel, и в LibreOffice Calc.

## Помощник на Claude (необязательно)

На шагах «Столбцы» и «Муниципальные образования» есть кнопка «Уточнить с помощью ИИ».
Она нужна, когда заголовки или названия в файлах сильно отличаются от привычных.
Требуется свой API-ключ Anthropic; ключ хранится только во вкладке браузера
(`sessionStorage`) и отправляется напрямую в `api.anthropic.com`. Без ключа страница
работает полностью — сопоставление идёт по правилам: нормализация названий, отбрасывание
слов-типов («муниципальный район», «городской округ», «ЗАТО») и сравнение по Левенштейну.

## Разработка

```bash
npm install
npm run serve     # http://127.0.0.1:8765
npm run check     # прогон расчёта в Node на файлах из tools/testdata
npm run e2e       # сквозная проверка в браузере (Playwright)
```

### Структура

```
index.html            страница
assets/styles.css     оформление
src/xlsx/read.js      чтение .xlsx (распаковка zip + разбор XML листов)
src/xlsx/write.js     запись результата точечным патчем XML шаблона
src/core/detect.js    выбор листа, границы шапки, распознавание столбцов
src/core/match.js     сопоставление наименований муниципальных образований
src/core/aggregate.js агрегация строк реестра по строкам шаблона
src/core/build.js     заполнение шаблона и итоговая строка с формулами
src/core/report.js    контрольные суммы и отчёт о проблемах
src/ai/anthropic.js   необязательный помощник на Claude
src/ui/app.js         связка интерфейса
src/vendor/           fflate (MIT) — упаковка и распаковка zip
tools/                прогон в Node, сквозная проверка, скриншоты
```

Модули из `src/core` и `src/xlsx` не зависят от DOM и одинаково работают в браузере
и в Node (см. `tools/node-shim.mjs`).

## Публикация

Сайт разворачивается на GitHub Pages автоматически при push — workflow
`.github/workflows/pages.yml`.

**Один раз нужно включить Pages вручную.** Токен, которым работает workflow,
не имеет прав создавать сайт Pages, поэтому первый запуск падает с
`Create Pages site failed: Resource not accessible by integration`. Порядок:

1. Откройте **Settings → Pages** в репозитории.
2. В разделе **Build and deployment** выберите **Source: GitHub Actions**.
3. Перезапустите workflow: **Actions → «Публикация на GitHub Pages» → Re-run jobs**
   (или сделайте любой push).

После этого сайт будет доступен по адресу https://kamegaev.github.io/tko-mno/
и обновляться при каждом push.
